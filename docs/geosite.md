# Geosite

Это необязательный режим условия правила, а не VPN и не GeoIP. Остальные режимы работают независимо от базы. В `Rule` используются `mode: "GEOSITE"` и `host: "geosite:youtube"`; порядок и дополнительные условия не меняются.

## База и группы

В APK включён полный `dlc.dat` v2fly/domain-list-community от 02.10.2026 (1542 группы), переименованный в `geosite.dat`. Источник, commit и SHA256 находятся в `app/src/main/assets/geosite-source.txt`, MIT-лицензия — рядом. Проверка JVM читает всю реальную базу и проверяет hash, число групп и известные домены.

Группу можно найти в списке или ввести вручную: `youtube`, `geosite:youtube`, `google@ads`, `geolocation-!cn`. Регистр названия группы не важен. Несколько атрибутов через `@` объединяются AND; атрибут выбирает записи по наличию ключа, как V2Ray. `!cn` в имени/атрибуте является именем из базы, не оператором инверсии BrowserRouter. Неизвестная группа или пустая выборка сообщается в редакторе. Одна группа на правило; для OR создайте несколько правил с одним браузером.

Поддержаны все четыре типа Domain официальной схемы [V2Fly](https://github.com/v2fly/v2ray-core/blob/master/app/router/routercommon/common.proto): Plain — подстрока, Regex — поиск RE2/J, RootDomain — сам домен и поддомены через границу точки, Full — точное имя. RootDomain/Full нормализуются в ASCII IDN. Regex внутри базы использует поиск, в отличие от отдельного пользовательского режима REGEX (whole-host Java regex). `include:` уже раскрыты генератором `.dat`; текстовые исходники и sing-box `.srs` не импортируются.

## Хранение и импорт

SAF читает файл без разрешения на весь накопитель. Импорт файла и возврат к встроенной базе отключают автообновление и отменяют очередь ручного сетевого обновления. Лимиты: 16 МБ, 10 000 групп, 300 000 записей, значение до 2048 символов, до 64 атрибутов записи. Protobuf разбирается штатным CodedInputStream; запрещены deprecated groups, неизвестный тип Domain, дубликаты групп, повреждённые поля/UTF-8 и неподдерживаемый RE2. Импорт полностью валидируется до записи.

Пользовательский файл `files/geosite.dat` заменяет базу целиком через AtomicFile под общим process lock. Обе Activity используют один immutable снимок, все чтения/разбор/запись идут вне главного потока. Обновление APK меняет встроенную базу, но сохраняет пользовательскую. Возврат к встроенной удаляет пользовательскую базу после подтверждения и отключает автообновление. Правила остаются.

При отсутствующей/повреждённой базе и применимом geosite-правиле маршрут возвращает ручной выбор браузера вместо перехода к следующему правилу/fallback. Обычное более приоритетное совпадение продолжает работать; source/scheme/port/path проверяются до geosite. После импорта UI сообщает об активных правилах, групп которых нет в новой базе.

JSON v2 экспортирует правила, но не содержимое `.dat`; v1 читается. При переносе пользовательской базы сохраните её оригинальный файл отдельно. Системный Android backup включает config и пользовательскую базу. Настройки источника входят в JSON; статистика обновлений хранится отдельно и не содержит URL посещаемых сайтов.

## Сетевые источники и автообновление

Готовые источники: v2fly/domain-list-community, Loyalsoldier/v2ray-rules-dat и runetfreedom/russia-v2ray-rules-dat, каждый через raw.githubusercontent.com или cdn.jsdelivr.net. Можно задать дополнительный собственный HTTPS URL. Поддержаны прямые файлы, страницы GitHub raw/blob и ссылки на файлы Releases; не клонируется репозиторий целиком. Подход к готовым провайдерам и CDN сопоставлен с `throneproj/Throne` (`include/global/Const.hpp`, `include/configs/generate.h`); код Throne не копировался. Sing-box `.srs` по-прежнему не поддерживается.

Автообновление отключено до настройки пользователем. Переключатель, интервал 1–720 часов (по умолчанию 24), ограничение UNMETERED, сохранение источника и ручная кнопка находятся в Настройках → Geosite. Настройка `geositeUpdates` экспортируется вместе с правилами. Включение фонового обновления планирует первое выполнение при подходящей сети. Ручная кнопка сохраняет выбранный источник перед постановкой задания; при отсутствии сети ждёт подключения. Изменение настроек отменяет старое ручное задание. Очередь не блокирует редактирование источника.

AndroidX WorkManager 2.11.2: unique periodic work с UPDATE, unique manual work с REPLACE, CONNECTED/UNMETERED constraints, exponential backoff 30 минут и максимум две повторные попытки после ошибки сети. Периодические задания сохраняются после перезапуска устройства, но интервалы не являются точным расписанием: действуют Doze, батарейные ограничения и force-stop. Foreground service не используется. Открытие внешней ссылки не ждёт сети и использует последнюю локальную базу.

Транспорт — стандартный HttpURLConnection с системным TLS, без отключения проверки сертификатов. Только HTTPS, максимум пять перенаправлений; переход к HTTP запрещён. Таймаут подключения 15 секунд, чтения 20 секунд, общий бюджет 120 секунд; скачивание ограничено 16 МБ даже без Content-Length. Пустой/повреждённый ответ не меняет базу. Сервер/CDN выбирает пользователь; списки не подписаны BrowserRouter, доверие основано на выбранном источнике и HTTPS. CDN может отдавать кэшированную версию.

Перед записью валидируется вся база. Конфигурация, файл и проверка актуальности используют общий monitor. Устаревшее задание не заменяет базу после изменения источника/настроек, импорта файла или сброса. Версия локального файла сохраняется отдельно, чтобы защита работала после смерти процесса. Успех/ошибка и время последнего успешного обновления видны в настройках; при пропавших группах выводится предупреждение.
